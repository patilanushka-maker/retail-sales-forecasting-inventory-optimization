# Data Dictionary & Schema Specifications

> **Overview**: Defines canonical raw schemas, data types, allowable ranges, and source provenance for the datasets used in the system.

---

## 1. Raw Sales Transaction Schema (UCI Online Retail)

- **Source Reference**: [UCI Machine Learning Repository: Online Retail Dataset](https://archive.ics.uci.edu/dataset/352/online+retail)
- **Source Format**: Microsoft Excel (`Online Retail.xlsx`) or CSV dump.
- **Dependency**: Reading `.xlsx` workbooks requires `openpyxl>=3.1.0`.

| Field Name | Type | Nullable | Example / Domain | Description & Ingestion Rules |
| :--- | :--- | :--- | :--- | :--- |
| `InvoiceNo` | `string / int` | No | `536365`, `C536379` | 6-digit transaction invoice ID. Prefixed with 'C' if cancellation. |
| `StockCode` | `string / int` | No | `85123A`, `22633` | 5-digit distinct product (item) code. |
| `Description`| `string` | Yes | `WHITE HANGING HEART...` | Nominal product name/title. Nulls exist for some wholesale adjustments. |
| `Quantity` | `numeric (int)` | No | $-80995$ to $+80995$ | Quantity per transaction line. Negative values indicate returns/cancellations. |
| `InvoiceDate` | `datetime / str` | No | `2010-12-01 08:26:00` | Date and time when the transaction was generated. |
| `UnitPrice` | `numeric (float)` | No | $\ge 0.0$ | Product unit price in sterling (£). Zero prices denote promotional/loss entries. |
| `CustomerID` | `float / int` | Yes | `17850.0`, `NaN` | 5-digit customer identifier. Null for guest/unregistered checkouts. |
| `Country` | `string` | No | `United Kingdom`, `Germany` | Customer residence/destination country. |

> **Deferred Preprocessing Decisions**:
> - How cancellations (`InvoiceNo` starting with 'C') and returns (`Quantity < 0`) are aggregated into daily net demand.
> - Treatment of non-product codes (e.g., `POST`, `D`, `M`, `BANK CHARGES`).
> - Imputation or filtering of missing `CustomerID` and `Description`.
> All these transformations are handled strictly within `src/retail_forecasting/data/preprocess.py`.

## 2. Processed Daily Aggregated Schema (`data/processed/daily_product_demand.parquet`)

Constructed after data cleaning, transaction classification, and product-lifespan zero-filling:

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `date` | `datetime64[ns]` | Contiguous daily timestamp index (normalized to midnight) |
| `product_id` | `string` | Cleaned uppercase SKU code (mapped from `StockCode`) |
| `demand` | `float64` | Daily aggregated positive sales demand ($\ge 0.0$) |

## 3. Feature-Engineered Dataset Schema

Generated by `build_feature_pipeline` in `src/retail_forecasting/features/build_features.py`:

| Feature Name | Derived From | Type | Description & Leak-Free Rules |
| :--- | :--- | :--- | :--- |
| `demand` | Target | `float64` | Target demand at date $t$ |
| `day_of_week` | `date` | `int64` | Day of week index (Monday=0 ... Sunday=6) |
| `month` | `date` | `int64` | Calendar month index (1-12) |
| `day_of_month`| `date` | `int64` | Day of the month (1-31) |
| `is_weekend` | `date` | `int64` | Binary flag (Saturday/Sunday = 1, else 0) |
| `lag_1` | `demand` | `float64` | Demand at date $t-1$ |
| `lag_7` | `demand` | `float64` | Demand at date $t-7$ |
| `lag_14`| `demand` | `float64` | Demand at date $t-14$ |
| `lag_28`| `demand` | `float64` | Demand at date $t-28$ |
| `rolling_mean_7` | `demand` | `float64` | 7-day rolling average (shifted by 1 day: $t-7$ to $t-1$) |
| `rolling_std_7` | `demand` | `float64` | 7-day rolling standard deviation (shifted by 1 day) |
| `rolling_mean_14`| `demand` | `float64` | 14-day rolling average (shifted by 1 day) |
| `rolling_std_14` | `demand` | `float64` | 14-day rolling standard deviation (shifted by 1 day) |
| `rolling_mean_28`| `demand` | `float64` | 28-day rolling average (shifted by 1 day) |
| `rolling_std_28` | `demand` | `float64` | 28-day rolling standard deviation (shifted by 1 day) |
| `is_model_eligible`| Features | `bool` | True if all 28-day lag and rolling features are non-NaN |

## 4. Inventory Simulation Parameters (`config/config.yaml`)

> **Note**: These values are operational simulation inputs and do not originate from historical retailer files.

| Parameter | Unit | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `lead_time_days` | Days | `7` | Mean lead time from order placement to stock arrival |
| `lead_time_std_days` | Days | `1.0` | Variability in supplier delivery duration |
| `default_service_level` | Ratio | `0.95` (95%) | Desired Cycle Service Level ($CSL$) |
| `z_score` | Standard Normal | `1.645` | $Z$-statistic corresponding to 95% service level |
| `holding_cost_annual_rate` | % | `0.20` (20%) | Annual inventory carrying cost as fraction of unit value |
| `order_cost_per_order` | Currency | `50.0` | Fixed setup cost to place and process a purchase order |
